# 本地视觉实验台

`/vision-lab` 用用户自己的门照片和本地录像建立可重复分析的实验记录。当前是离线录像的参考匹配与人工复核工具；真实 FPV 自动穿越、正反方向、实时计圈和通用性尚未通过验收。整体路线见[系统设计](designs/local-vision-timing.md)，精度门槛见[视觉实验规范](vision-lap-experiment.md)。

## 使用步骤

1. 从训练工作台的“视觉实验”打开新标签页，或直接访问 `/vision-lab`。
2. 导入本地 MP4/WebM 等浏览器可解码的录像。四合一录像先选择当前选手的左上、右上、左下或右下画面；单画面选择完整画面。
3. 导入自己的门照片，或把录像定位到门清晰可见的时刻，点击“从当前画面选门”。框选目标门，填写名字，保存门档案。每个用户使用自己的资料，无须安装 Python 或训练模型。
4. 选择最多 3 分钟的分析区间、采样频率和参考相似度阈值，点击“开始本地分析”。首次点击才获取模型与运行库。分析较长时可取消，保留已处理部分，未处理区间记录为缺口。
5. 点击候选定位录像，逐个确认、排除或“改时刻并确认”；漏掉的过门可在当前播放位置补记。每次操作填写理由并追加到修正历史，原始候选不变。
6. 第一次确认只建立起点，第二次确认形成一个起终点间隔。区间内仍有待复核候选、缺口或重合时间时标为不完整，不纳入最快已复核圈。一个起终点门不能证明中途完成了全部赛道。
7. 导出 JSON 保存完整分析与修正历史，导出 CSV 查看圈速表；门档案可另外导出。再次导出带新的唯一后缀，旧文件保留。下载提示只是浏览器已发起下载，不冒充磁盘写入确认。

普通用户的门档案是照片、框选范围和配置，不是重新训练的模型。外观完全相同的门可能混淆，需要选择可区分的起终点或增加明显图案，再用实际录像验证。

## 本地保存与恢复

独立 IndexedDB 数据库 `fpvhelper-vision-lab` 保存门图片和分析记录，不修改原有训练 Session schema。录像只保留文件身份和元数据，不复制整段视频，不将视频转成 JSON；原始 MP4/WebM 仍由用户单独保存。

重开页面后载入本机记录，再选择原录像。系统增量计算完整文件 SHA-256，匹配后才允许复核；相同文件名不足以匹配。复核还须使用分析时的裁切区域。断页留下的未完成分析恢复为已中断，保留未处理缺口，不伪装为完成。

导入同 ID 的门档案或分析记录会生成独立副本；外部分析记录明确标为 `imported`，其中的模型字段和人工确认不是本机重新分析的证明。存储失败时当前修改仍留在页面中，可导出或重试保存。浏览器清理站点数据会删除本地库，请保留 JSON、门档案和原录像备份。

两个标签页同时修改同一分析记录时，数据库事务会拒绝覆盖已保存的不同复核历史。冲突页面仍可导出自己的修改，再载入最新记录继续复核；不会静默丢弃另一页已经保存的确认。

主要 JSON 字段：

| 内容 | 记录方式 |
| --- | --- |
| 录像身份 | 名称、大小、时长、尺寸、完整 SHA-256 |
| 门与设置 | 门 ID/修订、图像 SHA-256、参考选区、视频裁切、时间范围、采样率和阈值快照 |
| 模型来源 | 固定模型 ID/仓库 revision/权重 SHA-256、WASM 后端；权重哈希是资源来源记录，不表示每次运行重新校验权重 |
| 候选 | 原始时间、证据区间、相似度、候选框和产生原因 |
| 复核 | 追加式确认/排除/改时刻/补记、理由和修正时间 |
| 中断 | 状态、已处理帧数和位置、未处理缺口 |
| 时间来源 | `timestampSource: video_seek_position`，由媒体位置估计，非逐帧 PTS |

目前不直接关联原有 TrainingSession、打杆时间轴或已烧入 OSD 的视频，也不自动把人工修正转换成模型验收预测。后续评估适配器需分别输出冻结的自动候选与独立人工真值。

## 真实模型与精度边界

当前基线是 [DINOv2](https://github.com/facebookresearch/dinov2) 的 [Xenova/dinov2-small](https://huggingface.co/Xenova/dinov2-small) ONNX q8 权重，Apache-2.0，模型约 24.5 MB。版本、哈希与运行库固定在 `lib/vision-model.ts`。推理在浏览器独立 Worker 内通过单线程 WASM 执行，每次只有一个推理请求，不占用串口轮询。

模型计算参考图与视频区域的特征相似度，再由简单的接近趋势规则提议复核点。它没有针对 FPV 门和穿越专门训练；相似度不是成功穿越概率，未出现目标的画面也可能得高分。所有模型事件默认待复核，不自动宣布有效过门。

2/5/10 fps 表示离线取样间隔 500/200/100 ms，不是播放帧率或精度承诺。时间来自视频 seek 位置；逐步移动播放位置也不保证对应真实解码帧边界。候选可能提前、滞后、重复或漏检，当前不满足物理过门 P95 ≤100 ms 的验收要求。人工确认后的间隔用于训练复盘，不代表模型已经达到验收门槛。

首次模型加载会访问 Hugging Face 的模型资源及其文件分发域、jsDelivr 的固定版本运行库；参考图和视频不上传。已缓存资源可能被浏览器清理，当前没有承诺断网冷启动；不会因尚未点击分析而预先下载模型。

## 已完成验证与下一步

2026-09-05 的本地 Chromium 实验使用自制合成照片和 4 秒视频，通过真实 Worker、真实固定权重和 WASM 完成 8 帧分析：模型加载前没有外部请求，加载后只有资源 GET，没有素材上传；完成后 Worker 释放。单帧推理约 270–291 ms，仅代表该机器与合成片段。不同场景的最高相似度约为 0.80 和 0.67，不能作为真实门识别准确率。

同日生产构建独立复测也完成 8 帧真实推理（约 291–339 ms/帧），保存 1 个待复核候选、0 个确认圈，6 个外部资源 GET，无页面、网络或 HTTP 错误，Worker 已释放。首次尝试在权重 CDN 下载阶段触发 180 秒超时，重新运行后通过；首次联网资源可用性仍会影响启动，不应把成功重试解释为断网可用或下载永不失败。最终 `npm run check` 通过 543 项单元测试、类型检查和 Lint，生产构建与 21 项浏览器流程测试通过。

仓库测试覆盖候选与圈速规则、导入格式/哈希、保存事务、取消/旧回包隔离、恢复、修正后重算和导出。浏览器工作流测试使用合成素材与导入的候选夹具，验证产品行为；不把夹具当作模型识别成绩。

本地回归命令：

```bash
npm run check
npm run test:e2e:smoke
```

真实模型验证单独运行，不依赖用户文件，不放进默认离线测试。先在空闲端口启动隔离的服务，再在另一终端运行脚本；命令会访问真实模型资源。不要把测试指向正在训练的服务。

```bash
npm run build
npm run start -- --hostname 127.0.0.1 --port 3111

# 另一终端：
node scripts/smoke-vision-model.mjs http://localhost:3111
```

脚本使用仓库内的合成照片和 4 秒录像，验证 8 帧真实推理、模型版本、未发生网络写入、Worker 释放，以及实际保存的候选仍待复核、已复核圈数为零。报告和截图写入已忽略的 `output/playwright/vision-model-smoke/`；合成结果仍不能证明 FPV 检测精度。

下一步是在用户可独立配置的前提下建立跨门型、场地和图传的真实 FPV 样本及负例，冻结阈值和测试集，输出漏检/误报/重复/时间误差报告。之后再选择或训练专用检测与时序模型，接入一条实时采集卡流；保留原 100 Hz RC 采集目标、20 Hz 历史刷新和现有视频＋摇杆 OSD 录制行为。
