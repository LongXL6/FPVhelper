# 打杆实时监看中的过门计时

实时计时在飞行工作台的视频旁显示紧凑摘要，完整配置与复核面板位于画面与打杆区域下方，无须先录成文件再进入实验台。它复用当前选手的取景和[视觉实验台](vision-lab.md)中的门档案；每次分析一个起终点门、一路选手画面。

当前版本生成待人工确认的穿越候选。确认两次穿越才形成第一圈，有待复核事件或观察缺口的区间不纳入最快已复核圈。单门无法验证完整赛道，也无法仅凭相似外观保证正向穿越。

## 开始使用

1. 打开视频输入，选择当前选手并确认姓名。四合一输入先通过“裁切与绑定”选择该选手的区域，实时计时复用这个取景。
2. 在“实时过门计时”选择本机门档案。没有档案时展开“配置新的计时门”，截取当前取景或导入 10 MB 内的 PNG/JPEG/WebP 照片，框选门框、填写名称，再点“保存并绑定计时门”。录像实验台的门档案可直接共用或导入。
3. 如需同时保存视频与打杆数据，先用原来的“开始记录”开启训练录制，再点“开始过门计时”。本轮将记录真实训练 Session ID，但不宣称时间同步。仅观察画面也可独立开始计时。
4. 首次开始会下载约 24.5 MB 的固定模型及运行库。门照片和视频画面留在本机，未点击开始不会加载模型。模型准备期间计为观察缺口。
5. 查看待确认的穿越，填写理由后确认、排除或改时刻。现场观察到穿越时，可填写人工理由并点击“人工确认一次穿越”；采用点击时的主机时间，仍包含人工反应延迟。
6. 停止过门计时后继续查看、复核和导出。停止只释放识别使用的 Worker 和借用的视频元素，原视频流与训练录制由原来的按钮控制。

切换选手、视频源、裁切、门档案或训练记录会结束本轮，避免混合来源。切换工作台内部视图不会卸载识别；浏览器标签页转入后台、视频断开或超过 2.5 秒没有新帧会中断。每轮最多 30 分钟，之后需明确开始下一轮。

## 保存、复盘与分享

独立 IndexedDB 数据库 `fpvhelper-live-vision` 保存记录，门档案仍在 `fpvhelper-vision-lab`。不修改原训练数据 schema，不把视频编码进 JSON。视频仍按原流程另存 MP4 或浏览器支持的 WebM，并保留打杆 OSD；本版本计时数字显示在网页面板中，尚未烧入录像。

| 内容 | 保存方式 |
| --- | --- |
| 来源 | 视频源 ID、选手 ID/姓名、流与轨道 ID、尺寸、归一化裁切范围、可选训练 Session ID |
| 门与模型 | 档案 ID/修订/图像哈希/参考选区，固定模型 ID、revision、权重来源哈希和 WASM 后端 |
| 时间 | `host_presentation_estimate`，主机单调时钟与时间原点；可用时附视频回调的媒体位置、帧序号和呈现时间 |
| 原始观察 | 已处理新帧时间、推理耗时、待复核候选及其证据区间 |
| 修正 | 追加式人工确认、排除、改时刻、补记和理由；保留原始候选 |
| 缺口 | 模型准备、帧回调跳跃、推理覆盖不足、中断尾段；不补造连续数据 |

每 10 个分析帧暂存一次，复核和正常停止也保存。重开页面可从“恢复本机计时记录”读取历史；未正常结束的旧记录标为中断，未知结束时间保持未知，不自动恢复识别。

JSON 保存完整档案，CSV 提供圈速表；每次导出使用新的唯一文件名。下载发起不等于磁盘写入完成，请确认浏览器下载结果。保存失败时保留当前页结果供重试或导出；只有重试保存成功，或用户明确点击确认当前 JSON 下载完成后，才能切换记录或开始下一轮。多标签页保存拒绝覆盖不同的原始观察或复核历史。浏览器清理站点数据会清除本地库，原视频和导出的档案需要自行备份。

## 性能与验证范围

实时识别使用与离线实验台相同的固定 DINOv2-small q8 权重和单线程 WASM Worker。目标每秒最多分析 2 个新画面，每次只允许一个推理请求；忙碌时丢弃额外待分析帧，不积压视频。原串口 100 Hz 采集目标和 20 Hz 历史更新逻辑保持不变，但并行工作仍会占用本机 CPU，实际设备上的长时间性能需要实测。

500 ms 的目标取样间隔和浏览器呈现时间均不代表物理过门精度；没有曝光时间、采集卡延迟、视频与打杆偏移校准。相似度不是穿门成功概率，候选必须复核。默认浏览器测试中的模拟设备与导入事件用于验证程序行为，不能代表模型准确率。

真实模型链路可在隔离的本地服务执行，使用 Chromium 自带合成摄像头，获取真实模型资源，不接触用户采集卡或录像：

```bash
npm run dev -- --hostname 127.0.0.1 --port 3112
# 另一个终端；不要指向正在训练的服务
node scripts/smoke-live-vision.mjs http://localhost:3112
```

脚本验证实际共享视频流、至少 8 帧真实 Worker/WASM 推理、本地保存与导出、无素材上传，以及停止识别后保留采集轨道。报告与截图写入已忽略的 `output/playwright/live-vision-smoke/`。脚本通过也不构成真实 FPV 穿越、正式计时或四路运行验收。

2026-09-05 开发服务与生产构建分别完成 8 帧真实模型推理。生产构建单帧约 274–299 ms，只有一次摄像头获取，停止后共享轨道仍在线，导出与本地保存一致；6 个外部资源 GET，没有网络写入、页面或 HTTP 错误。本次首次模型准备约 101 秒，明确记为未分析缺口；下载耗时依赖网络与缓存，不能据此承诺立即启动。

同日类型检查、592 项单元测试、Lint、生产构建和 22 项浏览器流程通过。随后强化实时流程并在该生产构建上通过定向复测：真实 MediaRecorder、打杆合成器与 OPFS 并行运行，停止计时后仍录制，视频实际字节与容器头、写入收据、训练 JSON 和实时记录关联一致。该流程仅模型协议使用确定性测试响应；另一个真实模型实验验证推理，两类证据均不替代实际采集卡与飞行验收。
