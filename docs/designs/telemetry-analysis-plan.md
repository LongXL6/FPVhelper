# FPVHelper 遥控数据的分析价值与保存方案

更新：2026-09-05。本文区分已实现的数据基础与后续分析规划：本轮已接入 IndexedDB v2 分块、每秒确认检查点、历史摘要按需详情、采集质量/上下文，以及带摇杆 WebM 与原始 JSON 的同目录保存；自动分析、云同步和完整归档恢复未实现。实现不等于设备验收，当前验证边界见[集成审查](integration-review-2026-09-04.md)。

## 这些数据可以帮助回答什么

| 问题 | 可以计算或呈现的内容 | 解释时需要的条件 |
| --- | --- | --- |
| 选手如何使用摇杆？ | 四轴时间曲线、左右手二维分布、常用行程、端点停留时间、回中次数、左右方向使用差异 | 统一通道映射、端点、中心及单位；分布按时间加权，避免不均匀采样造成偏差 |
| 控制动作是否稳定？ | 操作变化速度、反向修正次数、短时摆动、同一动作的重复一致性 | 必须使用实际时间间隔，记录滤波和阈值；动作多或变化快不自动等于技术差 |
| 油门习惯是什么？ | 油门分布、高油门持续时间、快速加减油门、入弯前后油门变化 | 先有训练片段或人工标记；油门命令不能直接解释为推力、速度、能耗 |
| 四轴如何配合？ | Roll/Yaw、Pitch/Throttle 的同时变化、先后顺序、典型控制组合 | 结果反映输入的关联，不直接证明飞行因果关系；跨配置比较必须控制 rates/expo 等差异 |
| 炸机或撞门前发生了什么？ | 查看标记前后数秒的四轴输入，比较反复出现的操作组合 | 炸机、撞门的真值来自人工复核或可靠外部数据；不能由摇杆曲线直接判定 |
| 一段时间的训练有没有改变？ | 同一选手在相同练习中的重复性、误操作标记率、操控分布和有效练习时长趋势 | 要记录赛道、练习、设备和配置，保留全部尝试与失败；不能只比较成功片段 |
| 数据是否值得用于某项分析？ | 实际接收频率、样本间隔分位数、最长间断、链路状态变化、解析错误、可用时段比例 | 采集健康与训练成绩分别呈现；不把主机帧计数当成无线链路丢包统计 |

一个可直接落地的复盘例子：教练标记三次“撞门”，系统展示各自前后 5 秒的四轴输入，并关联对应视频片段，比较是否出现相似的先后操作。最终判断由复核后的画面和训练情境支持，而不是自动给选手贴上“反应慢”或“疲劳”的标签。

采集质量摘要已接入记录详情。下一版分析建议先做四轴回放、事件前后对比和操控分布；跨选手评分、自动故障归因和机器学习应排在标注及数据可比性之后。

## 必须保留的含义边界

当前数据来自地面接收链路的 MSP_RC。它记录的是这一采集位置看到的 RC 通道值，不是无人机实际姿态、角速度、位置或轨迹，也不一定等于未经遥控器混控、曲线处理的物理摇杆位置。遥测解码包括 RC、ANALOG、STATUS_EX，另有 API_VERSION、NAME、GET_TEXT 的可选只读名称查询；见 `lib/telemetry.ts` 和 `lib/betaflight-device-name.ts` 的白名单与解码函数。

- 当前无法仅凭这些值得到实际轨迹、过门时间、碰撞事实、真实姿态误差、马达故障或空口端到端延迟。
- 平滑度可以描述输入变化，不能独立证明飞得更快、更好或更安全。疲劳、心理状态也不能从摇杆变化直接判定。
- 要分析指令与飞行响应的差异，需要关联同一次飞行的机载 Blackbox；若要分析线路、圈速和过门，应再接入具有明确时间基准的视频、计时设备或定位数据。Betaflight 的 Blackbox 可以提供 RC 指令、陀螺仪、PID 和电机等记录，具体字段取决于实际固件及记录配置。[官方说明](https://betaflight.com/docs/wiki/guides/current/Black-Box-logging-and-usage)
- 地面桥接器的电压和 MSP RSSI 不能自动当成机载电池电压、真实 RF RSSI 或 ELRS LQ。当前记录以 `groundBridge` 区分，见 `lib/training-session.ts` 的 `TrainingSessionSample`。

### ±1000 是显示坐标，原始通道值继续保留

现有代码把通常的 1000–2000 微秒通道范围映射为中心轴 −100%…+100%，油门映射为 0%…100%，见 `lib/telemetry.ts` 的 `normalizeRcAxis` / `normalizeThrottle`。正方形坐标已统一显示 −1000、0、+1000，默认范围内换算为 `显示值 = (通道值 − 1500) × 2`，越界显示钳制到端点；原始微秒不变。

Roll/Pitch/Yaw 的中心对应默认 1500 微秒。油门纵轴同样使用 −1000…+1000；其中心 0 代表 50% 油门，底部 −1000 才代表 0% 油门，并保留油门百分比。新记录的 `captureContext` 保存默认归一化定义；每个通道的实测最小值、中心值、最大值、方向和校准版本仍需后续实现，不能把默认映射当成实际设备校准。

| 已有复盘 | 查询、备注、油门概览、人工标记、采集/录像摘要；周报统计时长、人数、有效性、导出覆盖和冲突 | `components/session-library.tsx`；`lib/training-weekly-report.ts` |
| 多路与录像 | 单正式 Session 对应当前选手；完整/裁切画面烧录摇杆为 WebM，原始 JSON 同目录保存；成功收据入 Session，同步未校准 | `lib/stick-video-compositor.ts`；`components/flight-dashboard.tsx`；`lib/training-session.ts` 的 `withTrainingSessionVideoReceipt` |

这里的“100 Hz”是轮询目标。`estimatedRcSampleRateHz` 用首尾接收时间估算平均频率，不能替代间隔分布。`sequence` 是浏览器解码后递增，`performance.now()` 也在主机处理帧时取值，均不是发射端序号或设备生成时间，见遥测 hook 的 `applyFrame`。一批串口数据中多帧连续解析可能产生很短或相同的间隔，不能当成操作者动作的真实时间分辨率。

`captureQuality` / `captureContext` 是 schema v2 的可选 version 1 扩展。新完成记录自动生成，旧文件没有则保持缺失；存在时严格校验。间隔统计仅采用相邻正间隔，用线性插值计算分位数；零值、倒序和无效时间单列。可用时段仅连接同来源、正间隔且不超过 50 ms 的观测，缺口仅记录已观察样本之间的 >50 ms 间隔，不臆造头尾样本。该阈值是当前分析分段定义，不是新增训练有效性或 RF 丢包判据。

带摇杆视频的绘制使用当时最新主机样本，和视频帧没有共同设备时钟。训练停止后先冻结遥控样本，等待编码尾块写入和 WebM 关闭，只有成功且非空的收据才附上文件名、MIME、字节、起止时间与叠层说明，再完成 Session 和自动 JSON 导出。失败仍保存遥控数据，不能声明录像完整；`synchronized` 与 `videoOffsetCalibrated` 始终为 `false`。

当前 ANALOG 值会复用到后续 RC 样本，缺少自己的更新时间或新鲜度字段；当前链路状态、解析错误统计也没有随 Session 完整保存。因而 100 个样本中相同的电压值，不代表电压进行了 100 次独立测量。

## 保存方案：原始记录、索引、分析结果分开

本轮已将 Session 元数据与原始样本块分开写入 IndexedDB，并兼容迁移旧库；导出仍是完整 schema v2 JSON。本地原始数据、索引、归档与分析结果的长期分层方向如下，表中尚未出现在上面“已有实现”中的能力仍是规划，未实施云服务。

| 数据层 | 保存内容 | 用途 |
| --- | --- | --- |
| 原始样本层 | 不可变的已解码 `channelsUs`、来源、主机接收时间、流内序号；如设备真实提供，再添加设备时间/序号 | 保留重算能力，不被滤波、显示缩放或新算法覆盖 |
| 上下文与事件层 | Session/选手稳定 ID、练习与赛道版本、飞机与遥控配置、通道校准、固件、采集位置；标记、连接变化、采样间断、质量事件 | 保证数据可理解、可分组、可定位；未知字段明确为空 |
| 本地索引层 | Session 摘要和选手、日期、练习、设备、标记、质量、文件状态索引 | 快速筛选，列表页无需读取所有历史样本 |
| 归档层 | 原始数据文件、清单、分块顺序、样本数、起止时间、校验和、schema、录像关联和同步校准信息 | 换电脑后可重建索引，校验文件完整性，离线长期保存 |
| 分析层 | 从原始数据派生的分布、曲线摘要、片段和指标；保留算法版本、参数、输入校验和、质量筛选条件 | 允许比较、回溯和重算；原始数据始终不变 |

建议训练前只要求选手和练习，其余常用设备配置可从已确认的上一场继承。教练可用快捷标记记录事件，结束后补充结果与备注。应记录标记来源、标记者和是否已复核；人工按键时间与真正事件发生时间可以不同，复核修正应保留原值。

每条流维护自己的采样率与时间基准。RC 不应因页面绘图而少存；电压、状态也不应为了凑 100 Hz 被复制成伪独立观测。允许分析时进行有明确规则的重采样，但原始时间、数据缺口和原始值不变。连续相同通道值表示“保持摇杆”，不能按值去重。

时间使用单调时钟计算场内间隔，并保留 UTC 起始锚点、时区及 `streamId/segmentId`；重连或不同设备时钟需明确标识。单调时钟可避免系统时间调整影响本次采样间隔，但不自动解决多设备或视频同步。[W3C High Resolution Time](https://www.w3.org/TR/hr-time-3/)

## 建议实施顺序

### P0：先让珍贵数据完整、可找、可解释

1. **分块基础已接入，补容量与崩溃实测。** 检查点只追加新样本，单块最多 500 帧；样本块与索引原子提交，定时器每秒尝试且写入中跳过。界面只展示事务确认的保存进度。当前训练仍在内存保留全部样本，尚无独立容量/背压预算；突然退出可能丢失最后未提交部分，不能保证最多 1 秒。旧库原值保留，增加磁盘占用也需纳入迁移实测。
2. **摘要/详情拆分已接入，分页待做。** 列表和计数读取摘要与块键，不读全部样本；最新记录及点击详情按需重建，完整周报需主动展开。索引仍使用 `getAll()`，摘要中的标记与质量区间也会增长；下一步增加分页、元数据上限和按范围读取。
3. **间隔质量已接入，补流状态与分析规则。** 新记录已有间隔分位数、缺口/可用时段、时钟和异常计数；油门概览在 >50 ms 缺口、来源切换和非正间隔处断开。ANALOG 独立更新时间、状态新鲜度、解析错误变化尚未随 Session 完整保存，时间加权分析和插值规则也尚待实现。主机缺口不命名为 RF 丢包率。
4. **默认转换与收据已接入，设备校准待做。** 原始微秒与 ±1000 显示转换分开，`captureContext` 保存默认归一化，录像成功收据关联同一次 Session；实测通道校准、设备/练习版本与跨数据流稳定标识仍需扩展。
5. **长期归档与恢复验收。** 保留本地目录自动归档，添加文件清单、校验和、可恢复导入、同 ID 冲突处理、备份状态和抽样恢复测试。浏览器存储有容量及清理边界，可检测 `navigator.storage.estimate()`、申请持久化并报告结果，但仍需独立文件备份。[MDN 存储配额与清理说明](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)
6. **消除高频数据的导入瓶颈，当前限制未改。** 周报仍只允许单文件 5 MiB、总计 20 MiB、20 个文件，见 `lib/training-weekly-report.ts` 的 `MAX_REPORT_*`。此前一个 16 通道合成样本的量级估算约 338 字节/帧，100 Hz 的 5 分钟约 9.7 MiB；这不是当前真实导出的测量值，新质量元数据还会增加体积。后续应一起设计分块归档、按需解析和受控内存预算，不能只扩大限制。

### P1：让教练可以立即使用数据

- 做四轴共用时间线、两手轨迹回放、事件窗口比较和同一练习的多次叠加；在已有采集质量摘要上增加按片段解释。
- 在可用时段上计算时间加权指标，版本化滤波/阈值，并显示实际有效数据时长。
- 区分“是否计入正式训练”“是否完整保存”“哪些片段可供分析”。当前有效性门槛是至少 60 秒、300 个独立序号及其他条件，见 `lib/training-session.ts` 的 `assessTrainingSession`；本轮没有改变它，也不把它当成高频质量合格。短暂炸机、中断前片段仍有复盘价值。
- 在已有成功录像收据上增加文件重新定位、偏移/漂移、校准方法与误差。当前收据不证明文件仍存在，烧录最新主机样本也不构成逐帧对应。

### P2：扩展到飞行表现与长期训练研究

- 接入机载 Blackbox、可靠圈速/分段计时、视频人工复核，构建“输入—飞行响应—结果”的可追溯关联。
- 先按同一选手、同一练习、相近设备配置比较，展示样本量和差异范围；有足够控制条件后再考虑跨选手分析。
- 机器学习数据按 Session/选手/训练日划分训练与评估集，避免相邻片段泄漏；保留失败、未标注和低质量样本的原始记录，用明确规则决定是否参与模型训练。
- 多人同时正式采集应升级为一个训练活动关联多条选手 Session/数据流，而不是把四个输入混入当前一条 Session。是否需要跨设备同步，应在本地保存与恢复闭环验证后另行确定。

## 后续完整数据平台的验收目标

可以随机选择任一历史 Session，准确找到选手、练习、设备配置、原始样本、质量区间、标记和相关录像；能从归档文件在新的浏览器环境重建记录；能解释每一个指标来自哪些样本和算法版本；调整分析算法后能够完整重算。这是后续目标，当前只完成了前述本地数据基础与录像关联。

当前浏览器合成 WebM 已完成编码回放、烧录摇杆与冻结源中止验证，证据见集成审查；使用合成画面/RC 和内存 writable。真实飞控/UVC、真实目录持续写盘与权限恢复未验收，不能用这些结果替代。
