## 本次新增与修正

- 新导航隐藏展示但不卸载采集；停止与文件收尾后自动打开所选记录。
- 实际有效 RC 接收频率单独显示；真实首帧不继承模拟诊断值。
- 记录改为逐样本订阅，保留原来源、链路、通道与时间顺序检查。
- 历史记录搜索/筛选、任意记录备注和曲线/标记详情；导出包含当前备注。
- v2 旧草稿缺少本地墙钟时由有效 ISO 开始时间兼容恢复；显式无效值仍拒绝。
- 周报补齐 RX 链路丢失原因。
- 摇杆叠层支持方向键移动/缩放，零尺寸阶段忽略交互。
- 训练开始确认后的首批样本立即进入订阅；按序号去重，避免高频采样反复扫描全部历史。
- 同一记录的备注、手动导出和自动目录写入串行处理，避免旧结果覆盖新备注；区分已确认保存、浏览器下载已请求、取消和失败。
- 单标签页锁允许短暂释放交接，避免开发刷新误判占用；真正的第二标签页仍禁止设备连接。
- 裁切录像期间主动绘制画布，避免切换记录/设置页后依赖隐藏视频的展示回调。
- 旧记录的 UTC Marker 时间转换为本地时间显示，修正 DVR 复盘清单的时区偏差。
- IndexedDB 数据库升级为 v2，分离草稿/完成记录索引与样本块；每次检查点只追加新样本，单块最多 500 帧。新块与索引原子提交；约 1 秒定时尝试，进行中的写入不叠加，只有事务完成才推进已保存帧数与时间。
- 历史列表和计数使用不含 `samples` 的摘要，最新记录与选中详情按需读取，周报展开后再读取完整记录。旧 v1/v2 文件和旧库兼容迁移，保留旧值、隔离损坏记录，检查块编号、计数与本地校验值。
- 新记录结束时计算实际样本间隔质量与单位/时钟上下文；零值、倒序和无效间隔单独计数，正间隔统计中位数/P95/P99/最大值，记录 >50 ms 缺口和同来源可用时段。旧文件缺失这些扩展时不补造采集事实，也不改变原有效性合同。
- 油门曲线在 >50 ms 缺口、来源变化和非正间隔处断开，孤立样本仍显示为点，读取详情失败可重试；修复初次访问没有记录时的空详情判断。
- 开启录像会从当前选手完整/裁切输入生成带固定摇杆叠层的 WebM，与原始 JSON 使用同一授权目录；预览叠层关闭或切换页面不移除烧录内容。停止先冻结采样，等待 WebM 写入与关闭后才附收据、完成 Session 并导出 JSON。
- 只有非空录像成功 write/close 才有 `video.recorded:true` 收据；失败继续保存遥控数据并明确提示。收据含文件名、MIME、字节、起止时间和叠层说明，`synchronized:false`，烧录使用绘制时最新主机样本。

## 后续最值得做的重构

1. **扩大数据规模的实测边界。** 摘要/详情已分离，索引仍一次性读取，当前训练样本仍完整驻留内存；周报按需打开后仍读取全部记录。下一步需要分页、元数据规模控制、内存预算与长时慢设备实测。每秒检查点不是最多丢 1 秒的保证。
2. **录像重新定位与同步。** 成功收据已进入 JSON，但尚无文件存在性复查、持久录像句柄、可恢复录像索引或偏移/漂移校准。真实目录权限、断连与独立备份恢复仍须验收。
3. **继续缩小工作台协调组件。** 本次先抽出视频视图与记录库；设备连接和 Session/视频开始停止仍集中协调，便于核对原守卫。后续可按输入、训练、工作站边界提取控制层，避免一次同时重写并发逻辑与 UI。
4. **用真实设备数据决定质量阈值。** 采集目标不等于实收频率。当前记录的是主机接收间隔与 >50 ms 缺口，不是 RF 丢包；还需状态新鲜度、解析错误变化与持续录像写盘证据，再决定是否引入更严格的有效性规则。
5. **长期高频导入与归档。** 周报仍限制 20 个文件、单文件 5 MiB、合计 20 MiB，未在本轮扩大。分块文件归档、受控解析、恢复导入与备份证明尚未完成。

自动 ARM/AUX 分段、正式视觉计圈、模型推理、完整视频同步和生产云端配置没有在本次界面集成中宣称完成。

## 2026-09-05 摇杆刻度修正与数据分析规划

原因：原叠层外框等宽高，但内部坐标区使用不对称的上下/左右 inset，被标题和底部读数挤成矩形；侧栏仅约束最大高度也可能破坏宽高一致性。现在各坐标区明确使用等宽高尺寸，标题/读数不改变轴比例。

- 叠层、侧栏与非当前选手小摇杆都显示 −1000、0、+1000。当前读数使用同一归一化单位；采集、原始微秒和保存百分比不变。
- 正常空间最小叠层为 132 像素，普通模式实际坐标区为 76×76；最小简洁模式为 102×102。刻度在两个模式都可见，油门中心 0 明确说明为 50% 油门。
- 浏览器实际缩小验证通过：普通模式 98×98 → 76×76，简洁模式 102×102，非当前选手小摇杆 74×74。390 像素宽度下无横向溢出，侧栏及所有坐标区仍为正方形；检查时浏览器警告/错误日志为空。
- `npm run check`：51 个文件、301 项测试，类型检查和 ESLint 均通过；`npm run build` 与 `git diff --check` 通过。
- 新增 [数据分析与保存方案](telemetry-analysis-plan.md)，区分目前可计算的操控指标、需要更多数据的飞行表现，以及分块写入、索引、质量和归档的优先级。当时尚未实施的分块、摘要与质量基础已在下面一轮接入；分析平台与云同步仍未实现。

本轮文件：`app/globals.css`、`components/draggable-stick-overlay.tsx` 及测试、`components/flight-dashboard.tsx`、`components/video-workspace-display.tsx`、新增 `components/stick-axes.tsx`、新增 `lib/stick-display.ts` 及测试、`lib/stick-overlay-layout.ts` 及测试，以及 `README.md` 和三份设计文档。
