# FPVHelper UI 系统

本次设计以 `98b8576` 的完整功能为基础，统一视觉和工作流程。旧策略文档继续保留产品决策；当前界面与交互以本文和源代码为准。

## 产品主线

教练在现场确认选手、画面和真实遥控输入，开始训练，标记值得复盘的片段，结束后保存备注与文件。俱乐部通过历史记录和周报汇总训练证据。

最重要的三个入口：

| 页面 | 首要操作 | 次级操作 |
| --- | --- | --- |
| 飞行工作台 | 当前选手、真实输入状态、开始/停止、人工标记 | 多输入/选手绑定、裁切、叠层、保存与录像设置 |
| 训练记录 | 搜索、筛选、选择记录、曲线和标记复盘、备注、导出 | DVR 清单、合并周报、检查 JSON |
| 工作站设置 | 安装与接线说明、快捷键 | 实验功能、原始串口夹具、既有统计配置 |

切换页面仅隐藏视图，采集所有者、选手 controller、录像与训练记录器始终挂载。已展开的表单与未保存的备注在切换时保留。

日常工作台以飞手对应的画面、打杆叠层和录制为主，视频使用工作区全宽。遥控仪表、油门曲线和采集桥诊断移入默认收起的“遥控详细数据”，展开时才挂载显示组件，收起不停止采集或录制。

视觉功能统一由“工作站设置 → 实验功能”进入：录像视觉实验台保留 `/vision-lab` 独立页面；实时过门实验首次打开才加载并读取视觉数据库。离开实时实验页会释放推理资源并保存本轮结果；面板保留复核状态，返回不自动重启。已有门档案、历史记录和飞手绑定不迁移、不清除。

## 视觉语言

- 冷白底色与侧栏、石墨色视频画布、少量铜色强调。橙/蓝仅承担左右摇杆区分；错误、成功与演示使用独立语义。
- 中文以系统无衬线字体为主；时间、频率、RC 数值使用等宽与等宽数字，避免跳动。
- 标题、当前操作、状态、辅助说明具有明确层级。每页保留一个主要任务，不用一整页同等级卡片争夺注意力。
- 视频和实时输入保持高对比；配置面板在浅色区域。常用操作直接可见，详细配置用原生 `details` 展开。
- 侧栏在桌面固定，窄屏收为横向导航。表单、报告和多画面网格必须适应窄屏，不能以裁掉控件解决溢出。
- 组件状态完整覆盖加载、连接中、真实在线、模拟、停滞、链路丢失、错误、保存中、待重试和空记录。

## 交互契约

### 摇杆坐标与缩放

- 可拖动叠层、侧栏及非当前选手的小摇杆均使用正方形坐标区，横纵行程比例恒为 1:1；标题和读数不参与坐标区拉伸。
- 四轴统一标出 −1000、0、+1000，两个交叉轴共用中心原点；当前读数使用相同显示单位。普通与简洁模式都保留刻度。
- 显示行程是原有中心百分比的 10 倍；原始微秒、存储百分比及 100 Hz 采集目标保持原含义。油门轴中心 0 对应 50% 油门，底部 −1000 对应 0%。
- 正常空间下叠层最小外框为 132 像素，保证刻度可读；受限画布仍优先适应边界。侧栏最大坐标区 158×158。
- 数据保存和分析规划见 [遥控数据的分析价值与保存方案](telemetry-analysis-plan.md)。

### 刷新率与数据来源

- `MSP_RC` 目标保持 **100 Hz / 10 ms**；单个请求等待响应，超时后再允许重试。
- 遥测仪表随有效 RC 帧更新；历史与尾迹每 5 帧追加，目标 **20 Hz**，对应原有约 3 秒油门历史、约 1 秒摇杆历史。
- 接收频率来自最近 1 秒有效 RC 帧计数，不能用 React 提交次数或显示器刷新率代替。连接后的首秒是累计值，不外推为性能承诺。
- 演示模式仍为 20 Hz，并有明确水印。演示输入不能开启正式训练 Session。
- 首个真实帧清除演示电压和 RSSI。地面桥电压只表示地面采集设备，不能当作飞行器电池。

### 多视频与选手

- 每个 UVC 输入只建立一个 MediaStream，可以供多个选手视图共享。每位选手的飞控连接独立。
- 每个输入拥有四个稳定选手通道；切换全幅/四分屏不能卸载后台真实串口。
- 当前选手决定主仪表、Session 和可选 WebM 的归属。准备、录制、收尾期间锁住选手、输入路由、裁切与录制偏好。
- 自定义裁切用实际 Canvas 输出。录像合成器从共享输入按同一裁切参数绘制，再烧录左右摇杆、±1000 刻度、油门百分比、选手代号和链路状态。
- 录像采用固定独立叠层，不受预览叠层开关、拖动布局或页面导航影响。绘制时取最新主机样本，未校准视频与遥控时间。
- WebM 与该 Session 的原始打杆 JSON 自动保存到同一授权目录；结束合成流不关闭用于预览的共享 UVC 流。

### 训练与保存

- 开始前检查真实串口、RC 新鲜度、RX 正常、选手代号、存储和主标签页。
- 首个草稿确认存入 IndexedDB 后才进入录制；之后每 1 秒尝试追加检查点，单块上限 500 帧，写入尚未完成时跳过本次定时触发。
- IndexedDB 数据库升级为 v2，摘要索引与样本块分开存储；导出 JSON 仍为 schema v2。新样本块与检查点索引在同一事务提交，事务完成后才更新“已保存帧数 / 至哪个时间点”。意外关页恢复最近确认的草稿，1 秒调度不等于最多丢失 1 秒。
- 每个有效 RC 帧经独立订阅进入记录器，避免 React 合并渲染丢掉同批样本。链路/选手/中断守卫继续生效。
- 断链、切换输入、中断恢复使用原来的分类原因；保存失败提供重试，不宣称成功。
- 停止时先冻结遥控采样，等待伴随 WebM 写完并关闭，再将成功收据附入 Session、完成本机保存和自动 JSON 导出。收尾期间维持操作锁定，避免视频收据晚于 JSON。
- JSON、WebM 分别报告结果。只有文件 write 与 close 完成才显示确认写入；视频失败仍保存原始遥控数据，`video.recorded` 保持 `false`。浏览器下载请求不等于已确认文件。
- 记录列表、筛选与计数读取不含 `samples` 的摘要；最新记录和选中详情按需加载原始样本，周报展开后才读取完整记录。摘要尚未分页，当前训练仍在内存保留完整样本。
- 新完成记录保存 `captureQuality` / `captureContext` 版本化扩展。详情显示实际正间隔中位数、P95/P99/最大值、>50 ms 缺口与异常间隔；旧字段缺失显示“未记录”。主机采集质量不等于 RF 丢包，现有技术有效性门槛不随本次扩展改变。
- 油门概览在 >50 ms 缺口、来源切换或非正间隔处断开；详情读取失败可原地重试，切换记录后忽略较晚返回的旧详情。
- 每条历史备注最多 2000 字，保存错误留在编辑器内。导出包含当前备注草稿，并继续走可靠导出流程。
- 旧库迁移保留原始值，损坏记录隔离；块编号、计数与本地校验在读取时验证。兼容 v1/v2 文件及较早 v2 草稿缺少本地墙钟字段的情况；本地校验不是密码学归档签名。

### 快捷键与可访问性

- 原生按钮、label、details、可见焦点、主内容跳转链接。
- Space 长按 700 ms 开始/结束，松手/失焦/隐藏取消未完成长按。F/M/E 默认关闭；输入控件不被劫持。
- 摇杆叠层支持方向键移动/缩放，Shift 加速，成组锁定仍成立；隐藏视图不能改变布局。
- 错误和记录结果具有可读状态文本，不仅依赖颜色。

## 代码边界

- `flight-dashboard.tsx`：主工作区与开始/停止协调；保持原硬件和保存守卫。
- `video-workspace-display.tsx`：视频元素注册、真实裁切输出、每个选手的小型遥测视图。
- `stick-video-compositor.ts` / `local-video-recording.ts`：独立画面与摇杆合成、输入中断处理、本地分段写入与成功关闭收据。
- `session-library.tsx`：历史导航、筛选、详情、备注和复盘，不自行重写数据模型或文件导出。
- `session-capture-summary.tsx` / `session-report-loader.tsx`：采集质量与录像收据展示、周报按需读取。
- `use-betaflight-telemetry.ts` / `use-pilot-telemetry-workspace.tsx`：串口生命周期、100 Hz、解析、新鲜度、多选手隔离。
- `use-training-session.ts` 与 `lib/training-session*`：逐帧记录、分块恢复、摘要与详情、备注、伴随录像收尾、可靠导出；`training-capture-quality.ts` 定义实际样本的质量统计与时钟上下文。
- `workstation-runtime.ts`：单主标签页、唤醒和防误触快捷键。
- `app/globals.css`：统一语义色、布局、表单、报告和响应式外观。

## 尚需单独验收的范围

当前本地 WebM 与 Session 使用文件名中的 Session ID 和成功收据关联；收据不是本地文件存在性复查，也不包含可直接重新打开录像的持久文件句柄。尚无帧级同步、漂移校准或完整录像恢复索引。视觉过门已接入本机参考匹配，实时与录像实验均需人工复核；不能展示为自动正式计圈，精度与硬件边界见 [实时过门实验](../live-vision.md) 与 [录像视觉实验台](../vision-lab.md)。

浏览器合成画面已验证 WebM 编码回放、烧录摇杆和冻结源中止，使用内存 writable；详细证据见集成审查，不能代替真实目录和硬件验收。周报导入仍限制单文件 5 MiB、总计 20 MiB、最多 20 个文件；长期高频归档的按需解析、容量控制与恢复导入仍需后续实现。

真实 USB/飞控/采集卡的有效采样率、长时间稳定性、后台标签页表现和实际录像内容需要设备验收。单元测试、浏览器界面检查与构建通过不代表硬件、线上发布或业务验收完成。
